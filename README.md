# mistable

`mistable` is currently in **Phase 0: Minimal Spine**.

The current goal is intentionally small and concrete:

- build a Verilator simulation
- run it deterministically
- produce a real output artifact
- prove the repository structure and development environment are working

The output artifact for the current spine is:

- `build/frame.ppm`

This is a binary **PPM P6** image generated by the simulation.

---

## Current Baseline

The repository now has a hardened, repeatable container workflow.

Canonical entry points:

- Interactive container shell: `./dev`
- Environment verification: `./scripts/sanity.sh`
- Build + simulation smoke test: `./scripts/test.sh`

Canonical container/tool definition:

- `container/Dockerfile`

Canonical container runner:

- `scripts/docker.sh`

Shell defaults for interactive container sessions:

- `scripts/bashrc`

Golden smoke verification file:

- `sim/frame.ppm.sha256`

## Quick Start

### Enter the trusted container shell

    ./dev

### Verify the environment

Run this **inside** the container:

    ./scripts/sanity.sh

This checks:

- working directory
- tool availability
- repository contract
- write access
- git visibility
- simulation build and run
- output artifact generation
- artifact checksum verification

If this passes, the current baseline is healthy.

---

## Verification Workflow

The authoritative verification path is:

    ./scripts/test.sh

This script:

1. cleans previous build output
2. builds the simulation
3. runs the simulation
4. verifies `build/frame.ppm` exists
5. computes the artifact SHA-256
6. compares it against `sim/frame.ppm.sha256`
7. prints a success message

- `make sanity` — run the environment verification gate

---

## Initializing or Updating the Golden Hash

The first time you adopt checksum verification, or when an intentional simulation-output change occurs, refresh the golden hash with:

    UPDATE_GOLDEN=1 ./scripts/test.sh

Or, using the convenience target:

    make golden

This writes the current artifact hash to:

- `sim/frame.ppm.sha256`

Only do this when the output change is intentional and verified.

## Troubleshooting

### Permission denied writing to `build/`

If `./scripts/sanity.sh` fails with a write error under `build/`, the simplest fix is usually to remove the generated build directory and rerun the check:

    rm -rf build

Then re-enter the container if needed and rerun:

    ./scripts/sanity.sh

`build/` is generated output and can be recreated.

### Hash mismatch in `./scripts/test.sh`

If the simulation runs but `./scripts/test.sh` reports a checksum mismatch, that means the generated artifact changed.

First assume the change is unintentional and investigate.

If the output change is intentional and verified, update the golden hash:

    UPDATE_GOLDEN=1 ./scripts/test.sh

Or:

    make golden

Then commit the updated `sim/frame.ppm.sha256`.

### Sanity check fails after environment changes

Use the standard baseline sequence again:

    ./dev
    ./scripts/sanity.sh

Or:

    make shell
    make sanity

If sanity does not pass, treat it as an environment problem first before assuming the RTL or simulation is broken.
